# Windows 一键启动说明

日期：2026-09-27

## 最简单的用法

在 `AI-Novel-Writer-master` 文件夹中，双击：

```text
一键启动.bat
```

- **第一次**：如果缺少指定版本的 pnpm 或项目依赖，会出现 `Continue? [y/N]`。同意初始化时输入 `y` 并回车；输入其他内容或直接回车会安全退出。
- **后续**：环境齐全且依赖声明未变化时，直接检查原生模块并启动 Electron 桌面窗口，不重复安装依赖。
- **运行时**：保留启动器的控制台窗口；在该窗口按 `Ctrl+C` 可停止开发模式。
- **桌面入口**：可以为这个 BAT 文件创建快捷方式；不要只把 BAT 文件复制到桌面，它需要旁边的 `scripts` 目录。

这是修改后源码的开发模式启动器，不是新的 EXE 安装包。旧安装版不会因这次修改而自动更新。

## 启动器会做什么

1. 从自身位置确定项目目录，检查 `package.json`，不依赖终端当前目录。
2. 检查 Node.js 至少为 **22.13.0**。这是本项目 pnpm 11 的要求；Node.js 22 LTS 的较新版本适合作为起点。
3. 使用 `package.json` 声明的精确 pnpm 版本。已有合适版本就复用；没有时，经确认后下载到项目自己的 `.runtime/launcher/tools`，不更换系统全局 pnpm。
4. 检查依赖和 Electron 可执行文件。缺少依赖或已记录的依赖配置发生变化时，经确认后安装。仓库有锁文件时使用 `--frozen-lockfile`，不会自动删除或重写锁文件来绕过错误。
5. 执行现有 `rebuild:electron`，检查 / 准备适用于 Electron 的 SQLite 模块。首次准备可能下载原生模块或需要本机编译工具。
6. 尝试复用或启动**已经安装**的 Ollama。新启动的服务只绑定 `127.0.0.1:11434`；检测到自定义服务地址、现有进程或端口占用时，不强行启动第二个服务。
7. 执行 `pnpm run dev`，打开桌面应用，而不是只打开一个无法访问 Electron IPC 的网页。

重复双击由项目级互斥锁保护；如果应用端口 `5180` 已占用，启动器会提示检查现有程序，不会自动杀掉占用进程。

依赖初始化和原生模块准备阶段，遇到明确的临时网络错误（如 `ECONNRESET`、`fetch failed`）时，最多尝试 **3 次**，每次间隔 2 秒。仍然使用已有缓存和原来的下载源；不会自动换镜像、关闭 TLS 校验、删锁文件或升级 pnpm。非网络错误不自动重试，应用退出也不会被自动重启。

## 明确不会做的事情

- 不自动安装 Node.js、Ollama、Python 或 Visual Studio Build Tools。
- 不运行 `ollama pull`，不自动下载模型，也不发起生成请求。
- 不改变系统级 PowerShell 执行策略，不要求管理员启动，不修改全局包管理器。
- 不读取或更改小说数据库、模型 API Key、已有默认模型或向量索引。
- 不因本地服务不可用而切换云端。

BAT 中的 `-ExecutionPolicy Bypass` 只作用于本次启动的 PowerShell 子进程，不持久修改操作系统策略。脚本内容使用 ASCII，以兼容 Windows PowerShell 5.1；入口文件名和项目路径可以包含中文。正常启动时按 UTF-8 解码 Node 工具的输出，结束后恢复原控制台编码；只读检查不改变编码。源码与说明采用 LF 换行。

## 本地模型还需要单独准备

没有发现 Ollama 时，启动器仍会打开软件，并明确提示稍后配置模型。模型服务和模型权重仍须由用户自行准备；详见 [本地模型配置与验收说明](mcp-local-model-first.md)。

使用 LM Studio 时，请先在 LM Studio 中加载模型并开启本地服务器，然后在应用里选择对应配置。Ollama 服务即使由本启动器启动，也可能在关闭应用后继续后台运行；启动器不会主动结束已有模型服务。

打开应用后：

**模型设置 → 检测本地模型 → 选择已安装模型 → 测试连接 → 保存 → 按需要设为默认。**

## 日志与排错

启动日志位于项目内：

```text
.runtime/launcher/logs/
```

Ollama 启动日志也保存在这里。`.runtime` 已被项目忽略，不会作为源码提交。日志可能包含本机路径或开发调试信息，分享前请先检查。

| 现象 | 处理方法 |
| --- | --- |
| 提示 Node 不存在或版本过旧 | 安装 / 更新 Node.js 22.13+，重新打开启动器；脚本不会替你安装 Node。 |
| 下载依赖失败 | 等待有限次数的自动重试；仍失败时查看日志。普通 npm 包下载完成不代表 Electron / SQLite 二进制也已准备好；不要盲目删除缓存、小说项目或锁文件。 |
| 锁文件不匹配 | 先确认 `package.json` 与锁文件是否来自同一份源码；本启动器不会擅自更新锁文件。 |
| SQLite 原生模块准备失败 | 可能是预编译包下载失败或本机缺 Python / Visual Studio C++ Build Tools。按具体日志处理，不是所有机器都需要另装编译工具。 |
| 端口 5180 被占用 | 检查是否已有启动器 / 开发终端或其他服务；确认用途后自行关闭，再重试。 |
| 软件打开了，但不能写作 | 应用启动和模型可用是两回事；检查本地服务器、模型 ID、所选默认模型和实际上下文设置。 |

## 只读检查与回归命令

在项目目录打开终端，可运行：

```powershell
.\一键启动.bat /check
```

检查模式不安装依赖、不写启动日志、不启动应用或 Ollama。退出码 `0` 表示启动依赖检查通过，`2` 表示仍需初始化，`1` 表示错误或不满足 Node 等前置条件。它不证明模型生成或完整桌面流程已经通过。

维护者回归：

```powershell
node --test scripts/__tests__/one-click-launcher.contract.mjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/__tests__/start-local-windows.tests.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/__tests__/launcher-native-step.tests.ps1
```

两个 PowerShell 测试脚本使用自包含用例，不依赖 Pester，不会安装包或启动真实应用 / 模型服务；只在 `.runtime` 中创建唯一测试目录，结束后清理该测试目录。原生命令退出码测试仅运行自己创建的假 CMD 文件。
