# 墨墅 · 使用说明

**给灵感，一间自己的书房。**

不用先学会所有功能。第一次使用，只要走通下面这条路就够了：

**启动软件 → 连接模型 → 新建小说 → 故事架构 → 章节蓝图 → 写第一章 → 保存与定稿 → 导出**

> 墨墅是原 AI-Novel-Writer 项目的本地定制版。名字和界面换新，小说格式、模型配置和原有数据目录不变。

## 先记住这三句话

1. **墨墅是写作软件，不是模型本身。** 软件打开了，不等于 AI 已经能写作。
2. **保存、定稿、导出是三件事。** 保存留下修改，定稿确认章节，导出生成可分享的文件。
3. **小说文件夹最重要。** 导出一份 TXT 或备份启动脚本，都不能代替完整项目备份。

## 界面从哪里看

- **首页**：新建小说、打开作品、连接模型、查看使用指南，以及最近打开的作品书架。
- **左侧导航**：项目文件、小说资料、角色、蓝图、世界观和剧情；下方是任务、日志、模型调用记录及设置。
- **中间写作区**：打开文件后在这里阅读、编辑。任务面板和 AI 面板默认收起，按需打开。
- **右侧图标**：机器人是 AI 助手，星光图标是 AI 输出。
- **顶部**：新建、打开、拆解仿写、导出、指南、缩放、主题、语言与设置。窄窗口下部分操作只显示图标，鼠标停上去可看说明。

**随时查说明：**点击首页「使用指南」，或顶部的书本图标。

# 01 · 启动与连接本地模型

## 日常怎么打开

安装版从桌面“墨墅”启动；免安装版完整解压后运行 `Moshu.exe`。只有源码版才需要项目里的 **「一键启动.bat」** 并保留启动器窗口。正常退出请使用软件右上角的关闭按钮。

首次初始化或依赖变化时，启动器可能询问 `Continue? [y/N]`。同意下载项目依赖才输入 `y`。**项目依赖不等于模型**；启动器不会替你下载模型，也不会安装 Ollama、Python 或 Visual Studio。

## 先分清三样东西

| 名称 | 可以怎样理解 | 谁来准备 |
| --- | --- | --- |
| 墨墅 | 你的书房和编辑器 | 已在这个项目中改好 |
| Ollama / LM Studio | 让模型工作的机器 | 需要你自行安装并启动 |
| 模型 | 真正负责理解和写作的助手 | 需要在对应服务中自行准备 |

## 连接步骤

1. 准备完整的单文件 GGUF 写作模型。发行版内置了 Ollama 和 llama.cpp，不需要另装推理软件。夸克网盘入口已配置；点“夸克网盘下载模型”会在浏览器打开分享页，下载后回到此面板导入。已有文件也可以直接导入。
2. 打开 **「设置 → AI 生成模型 → 内置本地模型」**，点 **「导入 GGUF 文件」**。
3. 选择引擎（建议先 llama.cpp）、计算设备和上下文。模型要放在稳定目录，导入不会复制或删除原文件。
4. 点 **「启用并设为默认」**，软件会校验、加载模型并自动保存连接配置，无需手填服务地址。此按钮会按你的明确选择改变默认写作模型。
5. 模型显示就绪后，先在测试作品中生成一小段，确认质量和资源占用；加载成功不等于完整写作流程已经验收。
6. 外部 Ollama / LM Studio 仍可使用下方“本地模型快速配置”：检测列表、填写配置、测试、保存。外部快速配置不会自动替换已有默认模型。

默认本地地址：Ollama 为 `http://127.0.0.1:11434/v1`；LM Studio 为 `http://127.0.0.1:1234/v1`。若你改过服务端口，以实际服务设置为准。

> **能列出模型 ≠ 能生成文章。** 界面显示“已配置”也不是在线保证。先测试连接，再实际写一小段。

「AI 生成模型」负责写文章；「向量模型」用于资料检索。两者分开配置，暂时没有向量模型也能使用全文检索。想让写作留在本机，请明确选择本地服务，而不是云端配置。

# 02 · 新建小说，搭好故事骨架

## 第一步：给作品一个家

1. 首页点击 **「新建小说」**。
2. 填写作品名称，例如 **《风停在山海之间》**。
3. 点击 **「选择」** 设置保存位置。给每本小说单独准备文件夹，不要混进软件源码或其他小说。
4. 点击 **「创建项目」**。创建后，以软件显示的实际项目路径为准，记住它。

以后从首页 **「我的书架」** 继续写，或者点击 **「打开作品」**，选择原来的小说项目文件夹。不要把单个 TXT 当成项目目录打开。

## 第二步：在「小说配置」里说清故事

先用几句话回答四个问题：

- 主角是谁？
- 他或她最想得到什么？
- 最大的阻碍是什么？
- 故事大致会走向什么结局？

**可以参考这种写法：**

> 小城邮差收到十年前自己写给未来的信。他想找到写信的原因，却发现每送出一封旧信，就会遗忘一段自己的往事。最终，他必须在找回过去和保护眼前的人之间做出选择。

再填写题材、受众、写作语言、世界设定和写作风格。可以先简写，之后再补充。AI 填出的内容也要自己检查。

## 第三步：从整本书，拆到每一章

**小说配置 → 故事架构 → 章节蓝图 → 正文**

- **故事架构**：整本书的地图，包括人物、世界和主要情节。先生成或整理，再检查。
- **章节蓝图**：每一章的任务单。打开左侧「蓝图」，准备章节计划。
- **正文**：真正给读者看的故事，不是把蓝图原样复制出来。

先检查第一章：在哪里开场、谁出场、发生什么、结尾留什么悬念。**第一次先跑通一章，不必急着批量生成整本书。**

# 03 · 写第一章，分清保存与定稿

## 从蓝图开始写

1. 在章节蓝图中点击 **「写作此章」**。
2. 确认 **本次创作模型、章节号、目标字数、章节目的和关键事件**。本次选择模型不会自动改变全局默认模型。
3. 点击 **「开始创作」**，在左侧 **「任务」** 或右侧 **「AI 输出」** 查看进度。
4. 等待草稿生成。不要连续点击启动，也不要在任务运行中强行关闭软件。
5. 通读草稿，核对人名、时间线、情节和语气。需要时手动改写，或使用工具栏的修稿、审稿功能。

本地生成速度取决于模型、电脑和上下文长度。慢不一定是卡死；先看任务进度和日志。需要停止时，用任务面板中的取消操作，不要直接结束进程。

## 这三个词不要混淆

| 操作 | 它的作用 | 什么时候做 |
| --- | --- | --- |
| 保存 | 把修改留在项目里 | 编辑后及时做 |
| 定稿 | 确认这一章，更新后续创作所需记录 | 内容检查满意后做 |
| 导出 | 把已定稿章节生成 MD / TXT 文件 | 分享或整理正文时做 |

修改后留意顶部状态，有未保存内容时，使用当前编辑器的保存功能或 **Ctrl+S**。看到 **「已保存」** 再退出。不要只因为右侧出现了 AI 输出，就认为全部正文已经保存好了。

退出时若有未保存内容，软件会要求处理：可以保存并退出、放弃修改，或取消退出。**放弃会丢失未保存的修改。** 如果创作任务仍在运行，请先等待完成或取消任务。

## 什么时候开始下一章

确认这一章可以作为后续故事的依据后，执行 **「定稿」**。定稿不是发布作品，也不是普通的保存按钮。

后续章节通常需要上一章完成定稿。如果出现前置条件提示，先补齐它指出的蓝图或定稿步骤，不要靠反复点击绕过。

> **重要：导出只包含已定稿章节。** 只保存了草稿，导出时仍可能提示“无可导出的章节”。

# 04 · 导出、备份与常用设置

## 把正文导出来

先确认需要导出的章节已完成定稿，再点击顶部 **「导出」**：

- **纯文本 TXT**：给别人直接阅读，不需要格式标记。
- **合并 Markdown**：整本书放进一个 `.md` 文件。
- **分章 Markdown**：每章一个独立 `.md` 文件。

按需勾选 **「包含故事大纲」**，点击 **「选择目录并导出」**。看到成功提示后，到目标文件夹查看结果。当前小说导出提供 MD / TXT，不提供 Word 或 PDF 导出。

## 正确备份，别只备份正文

1. 保存正在编辑的内容，等待任务结束，并关闭小说项目或软件。
2. 找到这本小说的实际项目文件夹。
3. **复制整个文件夹**到另一个磁盘或你信任的备份位置。
4. 给备份标上日期，例如「作品备份-2026-09-27」。

导出的正文不包含完整的角色、设定、蓝图及项目数据库。模型配置和部分软件偏好也不在这一本小说的文件夹里；迁移电脑时需另外处理。**含 API Key 的配置不要公开分享。**

## 常用设置在哪里

| 想做的事 | 去哪里 |
| --- | --- |
| 连接或更换写作模型 | 设置 → AI 生成模型 |
| 调整主题、图片皮肤 | 设置 → 外观 |
| 调整字号和写作字体 | 设置 → 编辑器 |
| 放大 / 缩小界面 | 顶部缩放；或 Ctrl+加号 / 减号 |
| 恢复默认界面缩放 | Ctrl+0 |
| 找当前任务和报错 | 左侧任务 / 日志 |
| 查看本说明 | 首页使用指南 / 顶部书本图标 |

暖纸书房风是本次改版的浅色外观。你已有的主题、字体和皮肤选择不会被强制清空；如果还显示旧的深色选择，可以自行到「设置 → 外观」切换纸张主题。

**小心两个不同按钮：**「从最近项目移除」只清理列表；「删除项目」会删除真实小说文件。一定先读确认提示。

# 05 · 遇到问题，先查这一页

## 软件打不开

看启动器窗口最后的错误，并查看项目内 `.runtime/launcher/logs/` 的对应日志。

- 下载依赖时出现 `ECONNRESET` 或 `fetch failed`：先让启动器完成有限重试；网络恢复后再试。不要一开始就删除锁文件、缓存或重装全部工具。
- 已有一个窗口或端口被占用：先检查是不是已经启动，不要重复开多个启动器。
- 提示缺环境：按具体错误排查，不要把所有网络错误都当作缺 Python 或编译工具。

## 软件能打开，但模型连不上

先确认 Ollama 正在运行，或 LM Studio 的本地服务器已经启动。再检查服务地址、端口和模型 ID。

列表为空时，说明还需要在模型服务里自行准备模型。没有检测到模型，不代表墨墅会替你下载；本地连接失败也不会自动改用云端。

## 生成很慢，或提示显存 / 上下文不足

先尝试更小的模型、更短的上下文和更少的单次输出；关闭其他占用显存的程序。服务里的上下文设置与墨墅配置要相互匹配，不要直接照抄模型宣传的最大长度。

本机原先检测到的显存约为 6GB，并不适合随意把大模型和长上下文全部堆上去。具体模型能否顺畅写作，需要实际测试，不能只看模型名称判断。

## 无法写下一章，或者导出没有正文

- 不能写下一章：检查本章蓝图与上一章定稿是否完成。
- 导出为空：确认已经有**定稿章节**，而不只是保存了草稿。
- 导出提示定稿已变化：检查最新章节，重新确认导出。

## 求助时发什么

发送正在进行的操作、最后一段错误，以及对应日志时间。**不要发 API Key、完整个人配置，或不想公开的小说正文。**

---

**改名后的旧文件名是正常的。** 为保留兼容，工程目录、内部标识和安装配置中可能仍有原名。不要为了统一名字而手动改数据目录。上游项目更新可能覆盖这次本地定制，更新前先备份代码与小说。
