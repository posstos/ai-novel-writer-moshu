# 本地模型优先版：改造、使用与验收说明

日期：2026-09-27
范围：`AI-Novel-Writer-master` 桌面版，不修改独立插件或其他项目。

> **状态：源码改造与隔离环境回归已完成；本机真实模型创作闭环尚未验收。**
> 本轮没有在用户电脑上安装推理服务、安装项目依赖、下载模型、启动模型推理或打包安装程序。修改源码不会自动更新已安装的旧版桌面程序。

## 1. 本次目标与取舍

用户选择的是当前电脑本地运行、本地模型优先配置，不是云端开源模型 API，也不是集成下载器或模型运行器管理器。

复用项目已有的 OpenAI-compatible 请求、模型发现 IPC、两套设置入口与创作工作流。没有重写小说项目格式、数据库、定稿机制或提供方目录。

主要变化：

1. 新建生成模型和向量模型均从 Ollama 本地草稿开始，不再默认指向云端。
2. 不把目录中的示例模型当成已安装模型。新草稿的模型 ID 留空，用户检测后选择，或手动填写。
3. 两套设置入口均新增本地快速配置，支持 Ollama 与 LM Studio 的常用本机地址。
4. 本地兼容接口可以不填 API Key；模型列表、普通生成、流式生成和向量请求不再发送空的 `Bearer ` 头。服务启用鉴权时，仍可填写真实密钥。
5. 切换服务商时同步协议、地址、模型和能力，清空旧提供方的 API Key 与推理覆盖设置，避免把旧密钥带到新服务。
6. 生成草稿采用 2048 输出 token 的保守起点；上下文容量保持未知，不能从模型名字猜测服务器配置。
7. 本地请求不默认要求 `response_format` 或 `stream_options.include_usage` 扩展。确认服务支持并显式开启相应能力后才发送。云端既有行为保留。
8. 本地向量草稿使用现有低显存参数：每块 300 字符、重叠 30 字符、请求批量 4。

这些更改只影响新草稿或用户主动编辑后的保存，不自动迁移已有配置。

### 模型与资源建议

- 先评估 **7B 左右、四位量化的指令模型**，例如本机实际安装的 `qwen2.5:7b`。这只是起步候选，不是本次已经下载或测试的模型。
- 6GB 显存除了权重，还要承担 KV cache、运行时与桌面显示占用。不要把“权重能装入”当成“任意上下文都能流畅运行”。
- 不把 14B 设为默认起点。更大模型可能需要 CPU / 内存分担，速度必须实测。
- 先使用小型虚构测试项目、单章和短场景；不要直接用长篇生产项目、并行大批次或长推理模式压测。
- 先只验证生成模型。向量模型是独立配置；可以暂时不配置，避免一开始叠加显存压力。

## 3. 使用步骤

### 3.1 先准备本地推理服务

下面是**后续经用户确认后自行执行的示例**，不是本轮已经执行的操作。下载安装会产生网络流量并占用磁盘空间；模型使用还应遵守其许可证。

Ollama 路径：

1. 安装并启动 Ollama。若已在后台运行，不要重复启动第二个占用同一端口的服务。
2. 选择模型并完成下载。例如：

   ```powershell
   ollama pull qwen2.5:7b
   ollama list
   ```

3. 以 `ollama list` 和实际运行结果为准，不以本项目的模型预设列表为安装证明。

如果需要明确设置服务端上下文，可以使用自己的 Modelfile。例如：

```text
FROM qwen2.5:7b
PARAMETER num_ctx 4096
```

```powershell
ollama create vela-writer-7b -f Modelfile
```

这只是小上下文的配置示例，不保证完整创作提示词一定能放下。按实际显存与工作负载调整；应用中的“上下文窗口”应填与服务端一致的值。应用不会通过 OpenAI-compatible 请求自动替你调整 Ollama 的 `num_ctx`。

LM Studio 路径：加载适合当前硬件的模型，并启动其本地 OpenAI-compatible 服务器。端口、上下文与鉴权以 LM Studio 的实际设置为准。

### 3.2 在修改后的应用中配置

1. 按项目 README 的开发或构建步骤运行修改后的应用。当前改动不是已打包的新安装包。
2. 打开模型设置中的“本地模型快速配置”。
3. 选择 **Ollama** 或 **LM Studio**，点击“检测本地模型”。
4. 选择实际返回、且适合当前用途的模型，再点击“使用此模型填写配置”。这一步只打开未保存草稿。
5. 检查协议、地址、模型 ID、输出 token、实际上下文和能力选项。显示名称仍允许留空。
6. 点击“测试连接”，确认选中的模型能处理相应请求，再保存。
7. **如果原来已有云端默认模型，新增本地模型不会替换它。需要本地创作时，请主动设定本地默认模型，并检查任务及向量配置没有继续指定云端。**

常用配置：

| 服务 | 提供方 | 协议 | Base URL | API Key |
| --- | --- | --- | --- | --- |
| Ollama | Ollama | OpenAI-compatible | `http://127.0.0.1:11434/v1` | 无鉴权时留空 |
| LM Studio | 自定义 | OpenAI-compatible | `http://127.0.0.1:1234/v1` | 无鉴权时留空 |

如果端口不同或启用了鉴权，请使用普通表单手动配置。Ollama 的 `/api` 原生路径不是本应用使用的 `/v1` 兼容接口。

### 3.3 生成与向量模型分开选择

模型列表只是服务返回的目录，不保证每个条目都支持当前任务：聊天模型不能因此当作向量模型使用，向量模型也不能写正文。测试当前用途后再保存。

更换向量模型时，旧索引的维度与语义空间可能不同，应按现有项目的索引重建流程处理。此次改造不会自动替换模型、清理索引或迁移历史向量数据。

## 4. 创作流程的保守适配

本次保留现有生成预算、结构校验、失败恢复与定稿约束，没有为了适配小模型而放松这些保护：

- 不把输出截断、空正文或无法解析的结构化内容当成成功。
- 未声明支持结构化输出的本地接口，不发送强制 JSON 模式扩展；提示词与客户端结构校验仍然保留。
- 2048 token 是输出预算，不是中文字数保证。目标过长时应缩短章节或分段处理，而不是默认将截断文本定稿。
- 若上下文预算不足，先减少参考材料、缩短任务，或在确认资源允许后同步增加服务与应用的上下文设置；不要盲目填入模型宣传的最大值。
- 检测模型列表不会触发生成；保存配置不会执行创作流程；测试连接成功也不代表长篇质量已经合格。

真实验收应按以下顺序进行：

1. **写稿**：生成短场景，检查正文、完成原因、输出截断与语言。
2. **审稿**：生成可被现有结构校验接受的审稿结果。
3. **修稿**：按审稿建议生成新版本，不错误覆盖来源草稿。
4. **定稿**：核对定稿记录、项目连续性与后处理状态。
5. **重开项目**：确认本地数据可恢复，且下一章能引用正确的已定稿资料。
6. **故障用例**：停止服务、使用不存在的模型 ID、触发过小输出预算，确认明确失败而不是静默切换云端或误报成功。

以上真实模型步骤仍待执行，本次没有速度、显存峰值或小说质量的实测结论。

## 6. 修改范围与数据保护

- 新增共享本地端点策略与快速配置组件。
- 更新模型草稿工厂、两套设置 UI，以及发现 / 生成 / 向量调用的请求头。
- 新增本地接口和浏览器交互回归，并更新受默认值变化影响的测试。
- 新增 `vitest.local-model.config.ts`，将新交互测试纳入现有设置浏览器测试配置。
- 将快速配置组件纳入中英文覆盖扫描，更新中英文 README，并归档本说明。
- 保留已有提供方目录，包括当前 Ollama 的自定义预设条目；没有把它们当作已安装或适合本机的默认模型。
- 没有访问或修改用户的模型配置文件、API Key 文件、小说数据库、草稿、定稿、向量索引或默认模型记录。
- 没有安装或管理推理服务，没有自动下载模型，没有引入云端失败兜底。

“本地优先”不等于“强制断网”。现有云端配置仍然可用，用户主动选择云端时仍会向该端点发送内容；应用的更新检查也属于独立联网行为。判断数据去向应以实际配置与实际请求为准。
